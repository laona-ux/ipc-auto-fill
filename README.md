# ipc-auto-fill · 工控机自动填数工具

> 让笔记本把 Excel/CSV 里的数值，一条条自动「点进」工控机的小屏幕软件里。
> 每填完一条，等你人工确认无误后才填下一条（也支持校准模式自动试点）。

`ipc-auto-fill` 是一个**本地、单人、物理接入、人工确认**的录入辅助工具，适用于工控机（只有 USB-A 口、不能装软件、不能联网）的小屏幕录入场景。它通过一枚树莓派 Pico 把自己伪装成工控机眼里的「USB 键盘 + 鼠标」，由笔记本经串口下发指令完成自动填数，全程保留人工确认环节，杜绝误填。

## 方案原理

```
┌─────────────┐   USB线    ┌───────────────────────────────┐   USB口   ┌──────────────────┐
│ Windows 笔记本 │ ─────────▶ │ 树莓派 Pico（模拟成USB键盘+鼠标） │ ─────────▶ │ 工控机（只有USB-A口）│
│  读表格/发指令  │  (串口指令) │  插在工控机唯一的USB-A口上       │  (标准HID)  │  小屏幕上的软件     │
│  run.py/gui.py│            └───────────────────────────────┘           └──────────────────┘
└─────────────┘        ▲                │
                       │  CH340 USB转TTL串口线
                       └──(GP0/GP1 交叉接 RXD/TXD/GND)──┘
```

- **笔记本（上位机）**：读表格、计算坐标、下发指令、等待人工确认。提供图形界面（GUI）与命令行（CLI）两种形态。
- **树莓派 Pico（下位机）**：把自己伪装成工控机眼里的「USB 键盘 + USB 鼠标」，执行移动光标、点击、输入。约 ¥15，是「工控机不能装软件」场景下最便宜的 HID 注入方案——Windows 笔记本的 USB 口只能当主机，无法反向被识别成输入设备，所以必须有一个能模拟 HID 的小硬件。
- **串口链路**：笔记本与 Pico 之间用一根 USB 转 TTL 串口线（CH340/CP2102）通信，走 JSON 行协议。

**坐标定位**：工控机屏幕小、窗口位置固定，因此坐标基本固定。脚本用**相对移动 + Pico 内部记录上次位置**实现绝对定位（不必知道屏幕分辨率），每次运行前人工把光标移到屏幕左上角做一次 `home` 归零校准，之后全程自动。
> 若工控机软件能用 Tab 键在输入框间跳转，可把目标模式设为 `keyboard`，纯键盘导航，无需鼠标定位。

## 功能特性

- **Excel / CSV 导入**：支持 `.xlsx / .xlsm / .xls / .csv`，自动按扩展名区分；表头行/是否含表头可配，列名随意。
- **多列多行**：`row_start / row_end` 选填充范围；GUI 里可多选要填的列，一键生成整套「清空→输入→回车」步骤。
- **坐标定位（F8）**：GUI 内置方向键微调 + F8 级联写回坐标，另有 `--calibrate` 校准模式。
- **断点续传**：中断后从上次确认的行继续；断点绑定配置指纹，流程/列/范围变了会提示，防止按旧流程漏填。
- **人工确认**：每填完一行可暂停等你看清工控机确认后再填下一行（`confirm: enter/none`）。
- **GUI + CLI 双形态**：`gui.py` 可视化步骤流程编辑器 + 自定义按钮；`run.py` 命令行同等功能，共用同一份 `config.json`。
- **安全加固**：文本净化（拦截 `\n`/`\t` 控制字符）、按键白名单（禁 win/alt 危险组合）、断点配置指纹、审计 JSONL 日志、启动配置校验。
- **Dry Run 预览**：只打印指令序列不动工控机，便于调试。

## 快速开始

### 1. 需要购买的设备（约 ¥20～¥40）

| 设备 | 作用 | 建议 | 参考价 |
|---|---|---|---|
| 树莓派 Pico（RP2040） | 模拟 USB 键盘+鼠标 | 原版或兼容版，**不要买 Pico 2/RP2350** | ¥10～15 |
| USB 转 TTL 串口模块（CH340/CP2102） | 笔记本 ↔ Pico 通信 | 选带 **3.3V 电平/供电跳线** 的型号 | ¥3～8 |
| Micro-USB 数据线（**能传数据**） | Pico 连工控机 | 不要用充电线 | ¥5～10 |
| 杜邦线（母对母）×4 | 接 Pico GPIO 和 CH340 | 任意 | ¥1～2 |

### 2. 接线

| Pico 引脚 | CH340 模块 |
|---|---|
| `GP0`（UART0 TX） | `RXD` |
| `GP1`（UART0 RX） | `TXD` |
| `GND`（任意一个） | `GND` |

> ⚠️ 不要把 CH340 的 5V/VCC 接到 Pico 的 GPIO 或 3V3 脚（电平 3.3V，防烧板）；TX/RX **交叉接**；Pico 的 Micro-USB 插工控机 USB-A 口。

### 3. 安装

**Pico（一次性）**：按住 `BOOTSEL` 插电脑 → 拖入 CircuitPython 8.x 的 `.uf2` → 复制 Adafruit Bundle 的 `lib/adafruit_hid/` 到 `CIRCUITPY/lib/` → 把 `pico/boot.py`、`pico/code.py` 拷到 `CIRCUITPY` 根目录。

**笔记本（一次性）**：
```powershell
pip install pyserial openpyxl
```
在设备管理器里记下 CH340 的串口号（如 `COM3`）。

**工控机**：什么都不用装——Pico 插上即被识别为「USB 输入设备（键盘+鼠标）」。

### 4. 运行（命令行）

```powershell
cd host
copy config.example.json config.json   # 第一次执行
# 改 config.json：串口号、数据文件、步骤流程
python run.py
```

### 5. 运行（图形界面，推荐）

```powershell
cd host
python gui.py
```

## 配置说明（`host/config.example.json`）

```jsonc
{
  "com_port": "COM3",         // 笔记本上 CH340 的串口号
  "baudrate": 115200,         // 波特率，与固件一致
  "data_file": "values.xlsx", // Excel/CSV 文件（相对 host/ 或绝对路径）
  "sheet": "Sheet1",          // 工作表名，留空取第一个
  "header_row": 0,            // 表头所在行号（0-based）
  "has_header": true,         // false=无表头，自动按 col1/col2… 生成列名
  "row_start": 1,             // 只填从第几条（数据行，1-based）开始
  "row_end": 0,               // 填到第几条为止；0=到末尾
  "confirm": "enter",         // "enter"=每行人工确认；"none"=不停
  "start_home": true,         // 运行前归零校准原点
  "step_delay_ms": 300,       // 默认动作间停顿（毫秒）
  "steps": [ ... ],           // 步骤流程：对每一行数据按顺序执行一遍
  "buttons": { ... }          // 自定义按钮（可复用/快捷执行）
}
```

**步骤类型**（`steps` 中的每一项）：

| `type` | 作用 | 主要字段 |
|---|---|---|
| `click` | 移到 (x,y) 单击 | `x`,`y` |
| `dblclick` | 移到 (x,y) 双击 | `x`,`y` |
| `press_at` | 移到 (x,y) 按住左键 `ms` 毫秒 | `x`,`y`,`ms` |
| `move` | 只移动光标 | `x`,`y` |
| `scroll` | 滚动滚轮 | `delta` |
| `key` | 按一个键/组合键 | `key`, `times` |
| `input` | 填入数值 | `col`/`value`, `prefix`/`suffix`, `default`, `pre_keys`, `round`, `enter` |
| `sleep` | 等待 `ms` 毫秒 | `ms` |
| `home` | 光标回屏幕左上角并设原点 | — |
| `confirm` | 暂停等人点『已确认』 | `name` |
| `button` | 引用自定义按钮展开 | `name` |

> 核心思路：`steps` 是「步骤流程」——对表格的每一行数据按顺序执行一遍，所以能做到「点击进入某界面 → 填入数值 → 返回主界面 → 再进入另一界面 → 再点……」（工控机常见的翻页录入）。旧版 `targets` 配置仍兼容。

## 故障排查

| 现象 | 原因 / 解决 |
|---|---|
| 脚本报「找不到 COM 口」 | 串口号不对：设备管理器确认 CH340 的 COM 号，改 config.json |
| 脚本报「Pico 无响应 (ping 超时)」 | TX/RX 接反（对调）、波特率不一致、CH340 没插好 |
| 工控机没有任何反应 | Micro-USB 线是充电线（不能传数据），换一条；或 Pico 固件没烧好 |
| 光标点不到正确位置 | 重新校准；运行中有人动过工控机鼠标导致偏移（重新归零） |
| 点「停止」卡住不恢复 | 多为串口被占用/设备拔出；已加 3s 串口上限 + 12s 看门狗自动恢复 |
| 输进去的数值不对/多字 | 输入框有旧值 → 给 `input` 步骤加 `"pre_keys": ["ctrl+a"]` 先清空 |
| 想输入中文 | 不支持（USB 键盘协议限制），数值类需求用英文和数字 |

## 安全说明

- **文本净化（type）**：下发文本前拦截/替换 `\n`、`\t` 等控制字符，并限制长度（`MAX_TYPE_LEN=64`），防止 Excel 单元格里的换行/制表位被 Pico 转成真实回车/Tab 触发计划外按键。
- **按键白名单（key）**：仅放行 `enter/tab/esc/f1-f12/ctrl+a/ctrl+c/…/shift+tab` 等安全按键，**刻意不放 win / alt**，防误注入危险组合键；校验在生成阶段（上位机）即拒绝。
- **断点配置指纹**：`.progress` 记录步骤/范围/表头/数据文件的指纹（hash），两次运行间配置漂移会提示，防止按旧流程漏填。
- **审计日志**：每次运行的开始、每行填入摘要、是否确认、异常、结束都追加写入 `host/audit/*.jsonl`，可追溯。
- **配置校验**：启动前 `validate_config` 校验步骤类型枚举、key 白名单、button 引用、x/y 整数、col 有效、范围与 confirm 枚举，非法拒绝运行。
- **Excel 注入免疫**：用 openpyxl `data_only=True` 读取，不执行公式/宏。
- **运行边界**：这是**本地、单人、物理接入、人工确认**的工具，不联网、不云化；笔记本应视为「工控机的输入外设」，按 OT 资产对待。若填数记录具有质检/施工验收效力，建议上调为双人复核 + 不可删审计。
