# 工控机部署与可视化功能测试说明

> 适用对象：`ipc-auto-fill` 项目中「操作员控制台」（host 目录的 `gui.py` / `run.py`），  
> 配合已烧录 `ipc_auto_fill_esp32s3` 固件的 YD-ESP32-S3 开发板（替代原 Pico 的 USB 键鼠注入角色）。

---

## 0. 拓扑回顾（务必先理解）

```
【串口模式】                                  【无线(WiFi)模式】
[本机]  gui.py  ──(FTDI USB/COMx@115200)──▶  ESP32-S3  ──(原生 USB-C/OTG)──▶  [工控机] 表现为 USB 键鼠
[笔记本] gui.py  ──(WiFi TCP :8080)────────▶  ESP32-S3  ──(原生 USB-C/OTG)──▶  [工控机] 表现为 USB 键鼠
   ↑ 操作员坐这里，运行控制台、下发 JSON 指令                          ↑ 注入的键鼠落到工控机软件上
```

- **ESP32 的两个口分别接两台机器**：
  - 原生 USB-C（右口 / OTG）→ 插**工控机**，被识别为「USB 输入设备（键盘+鼠标）」，注入落点。**这条 USB-HID 注入线保留有线**，最稳。
  - FTDI USB（左口）→ 插**本机**，本机分配一个 COM 口（如 `COM12`），`gui.py` 通过它下发指令（**兜底通道**，与 WiFi 并行可用）。
- **无线控制（WiFi）**：ESP32 接入现场 WiFi 后，会在 `:8080` 上监听 TCP。此时 **`gui.py` 不必再插 FTDI 串口**——只要笔记本与 ESP32 在同一网段，填好 ESP32 的 IP 即可远程下发指令（见第 6 节）。ESP32 仍只用一根 USB-C 线接工控机供电+注入。
- ⚠️ **串口模式下** `gui.py` 必须运行在『本机』（FTDI 那台），因为 COM 口只出现在本机。  
  无线模式下无此限制，但**工控机上 ESP32 仍只表现为键盘+鼠标（OTG），工控机本身没有 ESP32 的 COM 口、也不能反向控制 ESP32**。
- 设备类型选择器（esp32 / pico）两者协议一致，仅作标识与配置持久化；选哪个都能正常收发与移动。

## 1. 部署到工控机

1. 把整个 `host/` 目录放到**运行 GUI 的本机**（即 FTDI 串口接的那台；U 盘 / 内网共享均可）。
2. 工控机安装 **Python 3.10+**，安装时务必勾选 **「Add python.exe to PATH」** 与 **「tcl/tk」**（tkinter 来自后者）。
3. 双击 `启动工控机填数助手.bat`：
   - 首次会自动建 `.venv` 并安装依赖（需联网；离线工控机请在有网机器 `pip download` 备好 wheels）。
   - 随后弹出「工控机自动填数助手」窗口。
4. 若工控机已离线：手动 `python -m pip install pyserial openpyxl xlrd` 后用 `python gui.py` 启动。

## 2. 可视化界面功能测试（工控机环境）

### 步骤 A：连接固件（在本机操作）

1. 确认 ESP32 **FTDI 口（左口）插在本机**、**原生 USB-C（右口）插在工控机**。
2. 在「连接与配置」区，**设备**下拉框选择当前固件类型（ESP32-S3 / Pico (RP2040)）；**串口**下拉框应能看到本机 FTDI 分配的 COM 口（如 COM12），点「刷新」可重新枚举。
3. 点 **「测试连接」**（或「自动检测」）→ 日志区出现 `ESP32 在线 ✅` / `PICO 在线 ✅`，表示 UART 链路+固件正常。
   - 若显示 `无响应 ❌`：**先确认 GUI 是运行在本机（不是工控机）**；再检查 COM 口是否选对、ESP32 是否供电、固件是否烧录。

### 步骤 B：载入表格

1. **数据文件**填入工控机上的 Excel 路径（如 `C:\...\注浆脚本.xlsx`），点「浏览…」选择亦可。
2. 点 **「载入表格」** → 左侧「选择要填入的表格列」列表出现表头列（桩号 / 稳定压力(MPa) / 注浆量(m³)…）。
3. 勾选需要填入的列 → 点「▶ 将选中列生成填入步骤」，主流程里会出现对应的「输入数值」步骤。

### 步骤 C：Dry Run 预览（不真注入，先验证指令流）

- 点 **「Dry Run 预览」** → 日志区打印将要下发的 JSON 指令序列（click_at / type / sleep / **confirm**）。
- 核对坐标、填入值是否与表格一致。无误再正式运行。

### 步骤 D：正式填数（真实注入）

1. 在工控机打开**被自动化的目标软件**，并把它摆到平时工作的窗口位置。
2. 勾选「开始前把鼠标归零到屏幕左上角」（默认勾选）。
3. 点 **「▶ 开始填数 (F9)」** → ESP32 经原生 USB 把键鼠注入到工控机软件；每行填完若勾选了「每行填完人工确认」会弹出确认框，按空格/回车继续。
4. 进度条与日志实时更新；「■ 停止 (F10)」可中止（进度已保存，下次 `--resume` 或界面续传）。

## 3. 物理 HID 核验（确认 ESP32 真的被工控机识别为键鼠）

插好原生 USB-C 后，在工控机 PowerShell 执行：

```powershell
Get-PnpDevice -PresentOnly -Class HIDClass | Where-Object { $_.FriendlyName -match 'USB' } | Select-Object FriendlyName, Status
```

应能看到新增的「USB 输入设备 / 符合 HID 标准的…设备」（即 ESP32 的复合键盘+鼠标）。  
若列表里**没有**新增 HID 设备，说明原生 USB-C 没插好或线材仅供电——键鼠注入不会生效，需更换数据线/接口。

## 5. 已知问题与排查（指令无响应）

- **现象：测试连接 / 移动 / 打字全部没反应**
  - **最常见原因：GUI 开错机器。** 按第 0 节拓扑，`gui.py` 必须运行在**本机**（FTDI COM 口所在的那台）。若开在工控机，工控机上没有 ESP32 的 COM 口，所有指令自然无响应。
  - 自查：在本机打开 GUI → 选设备 → 点「测试连接」，日志应出现 `ESP32 在线 ✅`。若在工控机开 GUI 则永远找不到 COM。
- **现象：方向键 / 跳转坐标点了没动**
  - 旧版逻辑要求先点「●归零」建立原点，否则静默返回（表现为"无反应"）。**新版已修复**：未归零时自动执行 home 建立原点，操作必有响应；定位期间复用同一条串口连接，点击不再因重开串口触发板子复位而丢首条指令。
- **现象：选了 pico 后移动仍正常**
  - 正常。pico 与 esp32 共用同一 JSON 协议，设备选择器仅作标识/持久化，不改变收发与移动逻辑。

## 6. 无线控制（WiFi）—— 去掉笔记本与 ESP32 之间的串口线

适用：想把 ESP32 留在工控机旁、操作员拿笔记本在 WiFi 覆盖范围内远程控制。ESP32→工控机 的 USB-HID 注入线**保持不动**，只把「笔记本→ESP32 的控制通道」从串口换成 WiFi。

### 6.1 固件侧（已内置，无需改代码）

固件已内置 WiFi + NVS 持久化，**不用改任何代码、不用重烧来换网络**。烧录后：
- ESP32 启动即尝试用 NVS 里保存的 WiFi 凭据联网；没有凭据时安静等待（不连 WiFi，也不影响串口/HID）。
- 联网成功后自动在 `:8080` 监听 TCP（与串口 COM12 并行，互不冲突）。
- WiFi 凭据存在 ESP32 的 NVS 里，**断电不丢**；换网络只需在控制台重新「保存并连接」。

### 6.2 控制台侧（首次配网 + 日常使用）

**首次配网（一次性，需先经串口连上板子）：**
1. 「连接与配置」区，**传输** 保持「串口」，**串口** 选好 ESP32 的 COM 口（如 COM12），点 **测试连接** 确认在线。
2. 在 **WiFi名(SSID)** 填现场 WiFi 名称、**密码** 填密码，点 **「保存并连接」**。
3. 固件把凭据写入 NVS（断电保存）并发起联网；控制台自动轮询 `net_info`，连上后把 ESP32 的 **IP 自动填入「IP」框**，并把 **传输自动切到「无线(WiFi)」**。
4. （若 20 秒内未连上，日志会提示 SSID/密码错或信号弱，核对后重点「保存并连接」即可。）

**日常使用：**
1. 「连接与配置」区，**传输** 已是「无线(WiFi)」，**IP** 已是 ESP32 地址，**端口** `8080`。
2. 点 **「测试连接」** → 日志出现 `ESP32 在线 ✅（192.168.x.x:8080）` 即成功。
3. 之后载入表格、Dry Run、开始填数等操作与串口模式完全一致——区别只是指令走 WiFi 而非 COM 口。
4. 笔记本必须与 ESP32 在**同一 WiFi 网段**。若 ESP32 的 IP 会变，可在路由器给其 MAC 做 DHCP 保留，或在「串口」模式下用 `net_info` 查当前 IP 再填回「IP」。

### 6.3 协议与可靠性说明

- 无线与串口**使用完全相同的 JSON 行协议**（`home` / `move_to` / `click_at` / `type` / `key` …），固件 `loop()` 同时处理两条通道，互不冲突。
- 单客户端模型：WiFi 同时只接受一个 TCP 连接（新连接会顶掉旧的），避免多个控制台抢同一条链路。
- WiFi 断线后固件每 5 秒自动重连；TCP 连接断开后，重连控制台即可恢复。
- 若 WiFi 不可用，把 **传输** 切回「串口」、插上 FTDI 仍可正常控制（兜底通道一直在）。
- 排错：若固件反复重启打印 `assert failed: xQueueSemaphoreTake`，属于 WiFi 栈过早初始化的构建问题（已修复：WiFiServer/WiFiClient 改为延迟到 WiFi 连上后再初始化）；重新干净编译烧录即可。
