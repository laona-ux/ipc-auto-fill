## 一、完善范围与设计取舍

按汇总报告「借鉴清单」的收益/成本排序，本轮落地了**纯软件、低风险、高价值、可单测**的 6 项（对 GUI 保持 `.progress` / `expand_steps` / `build_record_commands` / `save_progress` 等既有签名兼容，`gui.py` 无需改动即可正常复用）：

| # | 借鉴项 / 问题来源 | 落地内容 |
|---|---|---|
| 1 | 断点持久化加固（报告#6 + 可靠性 H1） | **确认后才写断点**：原本 `save_progress` 在行确认**之前**执行，用户发现错误退出后该行会被断点永久跳过（漏填/错值）。现改为**确认通过之后**才把该行记为完成。 |
| 2 | 断点状态持久化 / 配置漂移（可靠性 H2） | **断点绑定配置指纹**：`.progress` 增加 `steps_digest`（步骤流程+表头/范围+数据文件 mtime/size 的 SHA256），续传时检测漂移并警告，避免「改了流程仍按旧坐标续传」写错位置。 |
| 3 | 数据文件注入 / 文本净化（安全 R2/A1） | **type 文本净化**：拦截 `\n` `\t` 及其它控制字符（固件会转成真实回车/Tab 触发计划外按键），并截断到 64 字符上限。 |
| 4 | 任意 HID / 危险组合键（安全 A2） | **key 按键白名单**：默认只放行导航/功能/ctrl/shift 安全组合，**拦截 `win`/`alt` 等危险修饰键**；同时体现在「生成阶段抛错」+「启动配置校验」双保险（fail-fast）。 |
| 5 | 无审计留痕（报告#7 + 安全 A6） | **审计日志**：每行填入/干跑追加写 `host/audit/fill_YYYYMMDD.jsonl`（时间/行号/汇总/确认结果/状态）。 |
| 6 | 配置合法性 / 修复 CLI 整数列 bug（可靠性 H3/M9 + 报告#5） | **`validate_config()` 启动校验**（步骤类型、key 白名单、button 引用、坐标整数、列引用、范围、confirm 枚举）；**修复 CLI 对整数列号 `col:2` 误报「列不存在」**，与 GUI 行为对齐。 |

> 未纳入本轮的（报告中明确"可暂缓"或需硬件/结构改造）：协议层独立抽包（#1，涉及 __init__/导入结构）、图像/OCR 回读（#2，需摄像头与截屏基础设施）、步骤 DSL（#3，需新配置格式与 GUI 编辑器）、双人复核（P2）。这些更适合作为下一阶段、或在独立分支推进。

## 四、关键行为前后对比

| 行为 | 完善前 | 完善后 |
|---|---|---|
| 断点保存时机 | 行指令执行完、**未确认时**就 `save_progress` | 该行**人工确认通过后**才写断点（防漏填/错值固化） |
| 续传的安全 | 只比对 `data_file`，流程改了就错位续传 | 绑定 `steps_digest`，漂移即警告 |
| type 文本 | `\n`/`\t` 原样下发 → 固件转成真实回车/Tab | 控制字符替换为空格 + 64 字符上限 |
| key 按键 | 任意字符串都发 | `win`/`alt` 及危险组合被白名单拦截，生成与启动双校验 |
| 审计 | 无 | 每行 JSONL 落盘 `host/audit/` |
| 配置坏项 | 运行时才炸 or 静默跳过 | 启动 `validate_config` 一次性报出 |
| CLI 整数列 | 误报"列不存在" | 按列序号正确解析 |

## 五、兼容性与风险说明

- **GUI 兼容**：改动对 `gui.py` 复用的 `load_progress`/`save_progress`/`expand_steps`/`build_record_commands` 签名保持向后兼容；`save_progress` 新增的可选 `digest` 参数不影响旧调用。
- **旧断点兼容**：无 `steps_digest` 的旧 `.progress` 不会被拦截（`progress_is_drifted` 对旧格式返回 False，仅提示），用户可正常继续。
- **未做真机硬件测试**：本轮为纯逻辑 + 命令行 dry-run 验证；真正 `confirm="enter"` 发指令到 Pico 需在连 `/dev` 串口环境实测（不影响逻辑正确性，因发送路径未改动——仅调整 `save_progress` 调用位置与新增安全校验）。
- **运行方式**：`Set-Location host; python -m unittest discover -s tests -v`（无需安装 pytest）。
