# ipc-auto-fill · 项目介绍

> 对外介绍稿，可用于项目首页 / 宣传 / 技术分享。面向想了解「给工控机自动录入数据」这一场景的读者。

---

## 一句话

**ipc-auto-fill** 让笔记本把 Excel/CSV 里的数值，逐条自动「点进」工控机的小屏幕软件里——靠一枚 ¥15 的树莓派 Pico 伪装成 USB 键盘鼠标，全程保留人工确认，杜绝误填。

## 背景与痛点

工控现场（施工、注浆、压力监测等）大量使用小型工控机：屏幕只有 800×600 / 1024×768，只有 USB-A 口，**不能装软件、不能联网**，录入框坐标固定。操作员每天要把一批批 Excel 里的数值（桩号、压力、注浆量、转速……）手工敲进这些小屏幕软件里。这带来三个现实问题：

1. **繁**：几百上千行逐条手输，费时费力。
2. **易错**：连续录入极易敲错数字、串行跳行，而多数工控软件**错值不可逆、无撤销**。
3. **不可控**：无法保证「填完一条看一条」，也无法追溯什么时候填了什么。

市面上常见的自动化手段在这里大多不可用：远程控制（VNC/ToDesk）要联网和装软件；pyautogui/xdotool 只能控制**本机**屏幕；成品 BadUSB 键鼠模拟器坐标控制能力差、编程不透明。

**ipc-auto-fill 给出的是一个「把数值安全地送进不能动的工控机」的轻量方案**：数据在笔记本上准备，经一枚 Pico 以标准 USB HID 注入工控机，每填一条等人确认。

## 方案价值

- **零工控侧改动**：工控机不用装任何东西、不改任何设置，Pico 插上即被识别为「USB 输入设备」。
- **便宜**：全套设备约 ¥20～¥40（Pico + CH340 + 数据线 + 杜邦线），无需专用采集硬件。
- **安全可靠**：本地、物理接入、不联网；文本净化、按键白名单、断点配置指纹、审计日志、人工确认——错填漏填有兜底、有追溯。
- **灵活**：Excel/CSV 任意结构；`steps` 步骤流程支持「进界面→填数→返回→再进另一界面」的翻页录入；断点续传让中断后从上次确认的行继续；GUI + CLI 双形态。
- **可调试**：`--dry-run` 只打印指令不动工控机；坐标 F8 定位 + 校准模式。

## 差异化：和常见方案的对比

| 方案 | 能否控制「只有 USB 口的工控机」 | 坐标/定位能力 | 人工确认/断点 | 成本/复杂度 |
|---|---|---|---|---|
| **ipc-auto-fill（Pico + CH340 + 上位机）** | ✅ 专为此设计 | ✅ 相对移动绝对定位 + F8 校准 | ✅ 一键就有 | ¥20～40，低 |
| pyautogui / xdotool（纯软件） | ❌ 只能控制本机屏幕 | ✅ | ❌ 需自己写 | 低，但用不上 |
| 成品 BadUSB / 键鼠模拟器 | ⚠️ 能，但编程不透明 | ❌ 坐标控制差 | ❌ | 中 |
| 成品「CH9329 KVM」串口转 HID 芯片 | ✅ | 有限 | ❌ | 中 |
| 远程控制（VNC/ToDesk） | ❌ 要求联网+装软件 | ✅ | ❌ | 中，且不适用 |
| 树莓派 Zero 2W（USB OTG） | ✅ | ✅ | （本项目可选变体） | 约 ¥120，贵且复杂 |

> 一句话差异化：**「串口协议控制 HID 注入」+「Excel 到步骤逐行填写」+「断点续传」+「人工确认」** 这套**产品层组合**在开源界没有直接等同项目；最接近的 pyautogui/xdotool 只能控制本机，CH9329/ducky 系则缺少 Excel 驱动与人工确认这一层。

## 适用场景

- **工控/施工数据录入**：桩号、压力(MPa)、注浆量(m³)、转速、温度等，从 Excel 批量录入到不能装软件的工控机。
- **小屏固定窗口软件**：窗口位置固定、输入框坐标固定（坐标基本瞄一次就不再变）。
- **对准确性要求高的场景**：适合逐条人工确认；若记录具有质检/施工验收效力，建议配合双人复核 + 不可删审计。
- **完全离线现场**：不联网、不云化，纯物理注入，数据不出现场。

> 若工控机软件支持 Tab 跳转输入框，可切 `keyboard` 模式纯键盘导航，连鼠标定位都不用。

```powershell
copy config.example.json config.json
python run.py
```
