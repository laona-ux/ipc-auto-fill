## 1. 项目一句话

`ipc-auto-fill` 让 Windows 笔记本读取 Excel/CSV 表格，把数值经串口 JSON 协议下发给树莓派 Pico，由 Pico 以 USB HID（键盘+鼠标）注入到只能用 USB-A 口接入的工控机小屏幕上，逐条自动填入并保留人工确认。

## 2. 整体分层

```
┌─────────────────────────────────────────────────────────────┐
│ 上层 · 用户界面层（UI）                                        │
│   host/gui.py  Tkinter 图形界面（步骤编辑器/按钮/坐标定位/日志）  │
│   host/run.py  CLI 命令行（argparse：--config/--calibrate/     │
│                          --dry-run/--resume）                 │
└───────────────────────────┬─────────────────────────────────┘
                            │ 共用同一份 config.json，可混用
┌───────────────────────────▼─────────────────────────────────┐
│ 中层 · 填数引擎层（Engine）                                    │
│   host/run.py（run.py 同时承担装配与引擎）                      │
│   · 读表：openpyxl / csv → records                           │
│   · expand_steps()：steps/buttons 展开 → 每行指令序列          │
│   · build_record_commands()：记录 → 指令序列                  │
│   · 步骤引擎 run_once()：逐行执行、断点、人工确认、审计           │
│   · 配置校验 validate_config()、文本净化、按键白名单、断点指纹    │
└───────────────────────────┬─────────────────────────────────┘
                            │ JSON 行协议（串口）
┌───────────────────────────▼─────────────────────────────────┐
│ 底层 · 传输/链接层（Link）                                     │
│   host/run.py Link（serial，RFC 2217 串口）                   │
│   zero/mcp_hid.py、zero/run_on_zero.py（可选 Zero 2W 变体）    │
└───────────────────────────┬─────────────────────────────────┘
                            │ USB HID（键盘+鼠标）
┌───────────────────────────▼─────────────────────────────────┐
│ 固件层 · Pico（下位机）                                        │
│   pico/boot.py：仅暴露 HID，禁串口控制台（可选隐藏磁盘）         │
│   pico/code.py：串口指令循环 + HID 键鼠（相对移动绝对定位）       │
└─────────────────────────────────────────────────────────────┘
```

## 3. 核心数据流

```
Excel/CSV ─read─▶ records（一行一条） 
                    │  对每一条 record，按 steps 展开
                    ▼
          expand_steps(cfg) + build_record_commands(steps, record)
                    │  产出该行的一串指令（JSON）
                    ▼
          run_once / _run_rows：逐条下发
                    │  {"op":"click_at","x":..,"y":..}
                    │  {"op":"type","text":"25.5"}
                    │  {"op":"key","key":"enter"} ...
                    ▼
          serial（CH340） ──\n 分隔的 JSON 行──▶ Pico UART
                    │  Pico 执行一条回 {"ack":..}（或 error）
                    ▼
          Pico USB HID ──键盘/鼠标事件──▶ 工控机软件（填入数值）
                    │
                    ▼
          人工确认（confirm:"enter"）→ save_progress → 填下一行
```

**断点与审计**：
- `.progress`（`host/.progress`）：记录 `row/total/data_file/digest/time`；`digest` 是 steps+范围+表头+数据文件 mtime/size 的指纹（`_cfg_digest`），续传时校验，漂移则提示。
- `audit/*.jsonl`（`append_audit`）：每次运行开始、每行填入摘要、确认与否、异常、结束，全部追加记录。

## 4. 线程模型（GUI）

采用 **worker 线程 + queue + Event + 看门狗** 的经典模型，worker 线程**绝不直接碰 Tk**，通过 `queue` 把进度/日志消息投回主线程，主线程用 `root.after` / 事件循环消费：

- **主线程（Tk 事件循环）**：界面交互、发起运行、消费 worker 回传消息更新 UI。
- **worker 线程**：串口 I/O + 填数循环（`_run_rows` / `_button_worker`），可被「停止」通知打断。
- **可中断延时**：`sleep` 步骤可被停止事件提前唤醒。
- **看门狗**：停止路径最长 12s 强制恢复界面，串口打开有 3s 上限，避免「端口被占用/设备拔出」卡死。
- **run.py CLI**：单线程顺序执行（`run_once` 主循环）。

> ⚠️ 现状：行执行循环在 CLI/GUI/按钮三处各有一份（`run_once`、`_run_rows`、`_button_worker`），细节已分叉——这是已知的改进点（见 §6）。

## 5. 关键设计决策

| 决策 | 理由 |
|---|---|
| 用 Pico + CH340 而非软件/HID 直连 | Windows 笔记本 USB 口只能当主机，无法反向被识别成输入设备；工控机不能装软件/不能联网，只能物理 HID 注入。Pico 约 ¥15 最便宜可靠 |
| 串口走 JSON 行协议 | 人类可读、易调试；每行一条，Pico 执行完回 `ack`，天然成帧 |
| 相对移动 + 内部记录位置做绝对定位 | 不必知道工控机屏幕分辨率；`home` 归零后按 dx/dy 分步发 HID 相对移动 |
| `steps` 步骤流程 DSL（兼容旧 `targets`） | 支持「进入界面→填数→返回→再进另一界面」的翻页录入；DSL 更灵活 |
| 断点绑定配置指纹 | 防止两次运行间改了流程/列/范围仍按旧断点续传导致漏填/错填 |
| 人工确认（confirm） | 工控录入「错不可逆」，必须保留人在回路核对 |
| stdlib-only 单测（unittest） | 避免引入 pytest 依赖，`host/tests/test_run.py` |
| 原子写配置 + `.bak` | `tmp + os.replace`，防写坏 config |
| openpyxl `data_only=True` | 只取值、不执行公式/宏，对 Excel 注入免疫 |

## 6. 可维护 / 可扩展方向

**已知痛点（现状）**：
1. **行循环三份重复**：CLI/GUI/按钮三个循环已漂移 → 建议抽 `host/engine.py` 纯引擎 + hooks（log/confirm/sleep/stopped/progress 回调），`run.py` 瘦身为装配。
2. **协议契约四处平行维护**（host/run.py、pico/code.py、zero/、README §9）→ 建议加版本号 + 能力协商，抽 `schema.py` 单点维护。
3. **GUI 上帝对象**（gui.py 超千行，承担 8+ 类职责）→ 建议按「连接/表格/步骤编辑/坐标/运行」拆分成类/模块。
4. **配置与表格格式知识在 CLI/GUI 重复** → 抽 `tableio.py`（读 CSV/xlsx 统一）+ `schema.py`（配置校验单点）。
5. **无线程互斥**：GUI 启动双开竞态、`current_link` 多线程共享 → 加锁。

**已落地 / 进行中**：断点确认后保存、断点指纹、文本净化、按键白名单、审计日志、配置校验、CLI 整数列号修复、CSV 双保险（utf-8-sig→gbk）、测试套件。

**路线图（详见 README Roadmap）**：抽纯引擎、Link 抽象 + 工厂（abstract serial/Zero 后端）、串口分层重试/重连、ack 校验 op、运行期活跃探活、串口检测收敛（VID/PID）、pytest、可选隐藏 CIRCUITPY 磁盘 / 双人复核 / GPIO 急停。
